Résilience : timeout, retry, circuit breaker, fallback, bulkhead

La résilience consiste à empêcher qu’une panne locale devienne une panne globale.

MécanismeRôleExemple
TimeoutCouper l’attente excessive1 s pour un service de disponibilité
RetryRetenter un échec transitoire2 tentatives max avec backoff
Circuit BreakerStopper temporairement les appels vers un service maladeOuvrir après 50% d’échecs
FallbackRéponse dégradéeMessage “service indisponible”
BulkheadIsoler les ressourcesPool séparé pour un appel externe lent
 
@Retry(name = "catalogService")
@CircuitBreaker(name = "catalogService", fallbackMethod = "fallbackAvailability")
public AvailabilityResponse getAvailability(UUID bookId) {{
    return catalogClient.getAvailability(bookId);
}}

public AvailabilityResponse fallbackAvailability(UUID bookId, Throwable ex) {{
    return new AvailabilityResponse(bookId, false, "Réponse dégradée");
}}

Observabilité : logs, métriques, traces distribuées

Dans un système distribué, “ça ne marche pas” ne suffit plus. Il faut pouvoir répondre à trois questions : quoi, combien, où.

Logs

Événements horodatés, corrélés, lisibles par humain ou machine.

Métriques

Volumes, latences, taux d’erreur, saturation.

Traces

Parcours complet d’une requête à travers plusieurs services.

// Exemple d'enrichissement de log
log.info("loan-created loanId={} studentId={} correlationId={}",
        loan.getId(), loan.getStudentId(), MDC.get("correlationId"));

Bonne pratique

Adopter des logs structurés JSON en production, un identifiant de corrélation propagé entre services, et des dashboards métier + technique.

Monitoring, health checks, centralisation des logs

Un service n’est pas “vivant” seulement parce que le process tourne. Il faut distinguer liveness, readiness et dépendances.

management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus
  endpoint:
    health:
      probes:
        enabled: true

Sécurité inter-services : authentification, autorisation, JWT, OAuth2 / OIDC

Définition simple

Authentifier = prouver qui on est. Autoriser = vérifier ce qu’on a le droit de faire.

Mode enfant

Le badge d’entrée dit qui tu es. Les zones autorisées disent où tu peux aller.

Mode pro

Dans un SI distribué, l’identité et les droits doivent voyager de façon fiable entre services, sans faire confiance aveuglément au réseau interne.

@Bean
SecurityFilterChain security(HttpSecurity http) throws Exception {{
    return http
        .csrf(csrf -> csrf.disable())
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/actuator/health").permitAll()
            .requestMatchers(HttpMethod.POST, "/api/loans/**").hasRole("LIBRARIAN")
            .anyRequest().authenticated())
        .oauth2ResourceServer(oauth -> oauth.jwt())
        .build();
}}

Zero Trust et gestion des secrets

Zero Trust signifie qu’aucun segment réseau n’est implicitement digne de confiance. On vérifie l’identité, le contexte et le droit d’accès à chaque étape sensible.

Erreur fréquente

Mettre des mots de passe, clés API ou secrets dans application.yml versionné.

Bonne pratique

Utiliser un gestionnaire de secrets, limiter les droits, faire tourner les clés, tracer les accès sensibles.

Module DevOps / MLOps

Évaluation du rattrapage

Analyse de la solution rendue par l’étudiant

Appréciation générale

Le projet répond globalement aux attendus du sujet de rattrapage. L’étudiant a mis en place une API FastAPI fonctionnelle exposant un modèle de Machine Learning simple, avec sauvegarde du modèle, chargement pour l’inférence, conteneurisation Docker, pipeline CI/CD, monitoring minimal et documentation. L’ensemble est cohérent, structuré et exécutable.

Analyse par critère

1. Pipeline MLOps

La compétence est acquise.

L’étudiant utilise un dataset simple (iris), entraîne un modèle RandomForestClassifier, sauvegarde le modèle au format .pkl et prévoit son chargement pour l’inférence. La logique de chargement automatique du modèle, avec entraînement si nécessaire, répond bien à l’objectif attendu.

2. API REST

La compétence est acquise.

L’API implémente les endpoints demandés dans le sujet :

  • GET /health
  • POST /predict

L’entrée et la sortie sont bien gérées en JSON. Des endpoints supplémentaires (/version, /metrics) ont également été ajoutés, ce qui enrichit le projet.

3. Pipeline DevOps / CI-CD

La compétence est acquise.

Le pipeline GitHub Actions permet :

  • l’installation des dépendances,
  • l’exécution des tests,
  • l’entraînement du modèle,
  • la construction de l’image Docker.

Le besoin demandé par le sujet est donc couvert. L’étudiant va même au-delà avec l’upload de l’artefact modèle et la préparation du push d’image Docker.

4. Conteneurisation

La compétence est acquise.

Le projet contient un Dockerfile valide, un fichier docker-compose.yml, ainsi qu’une configuration permettant l’exécution locale du conteneur sur le port 8000. Le README documente correctement les commandes de build et d’exécution.

5. Monitoring

La compétence est acquise.

Le projet met en place :

  • des logs de requêtes,
  • des logs sur les prédictions,
  • un compteur du nombre total de requêtes,
  • un compteur du nombre de prédictions.

Cela correspond bien au monitoring minimal attendu dans le sujet.

Points forts

  • Projet propre et bien structuré
  • Respect des exigences principales du sujet
  • Présence de tests automatisés
  • Documentation claire
  • Bonus intéressants : Swagger UI, MLflow, docker-compose, workflow de release

Axes d’amélioration

  • Les tests restent simples et pourraient être approfondis
  • Le monitoring repose sur des compteurs en mémoire, non persistants
  • La séparation entre phase d’entraînement et phase d’inférence pourrait être encore mieux isolée dans une approche plus industrielle

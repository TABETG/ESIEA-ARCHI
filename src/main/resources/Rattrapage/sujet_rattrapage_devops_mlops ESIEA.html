Pipeline complet d'une API IA

Mini-projet individuel — 3 jours

Niveau Master Docker FastAPI MLflow CI/CD Monitoring

Vous devez mettre en place une application simple de Machine Learning exposée via une API REST. L'objectif est de démontrer votre capacité à intégrer des pratiques DevOps et MLOps dans un projet fonctionnel, conteneurisé et supervisé.

01 Compétences évaluées
  • Créer un pipeline DevOps
  • Créer un pipeline MLOps
  • Conteneuriser et monitorer une IA en production
02 Travail demandé
2.1 — Pipeline MLOps

Créer un modèle de Machine Learning simple avec scikit-learn.

  • Utiliser un dataset simple (CSV ou dataset intégré à sklearn)
  • Créer un modèle basique (LogisticRegression, RandomForest ou équivalent)
  • Sauvegarder le modèle entraîné au format .pkl
  • Prévoir un mécanisme de chargement du modèle pour l’inférence
Le modèle doit rester simple. L’évaluation porte principalement sur la mise en place du pipeline, non sur la performance du modèle.
2.2 — API REST

Exposer le modèle via une API développée avec FastAPI (recommandé) ou Flask.

  • POST /predict — retourne une prédiction à partir de données fournies en JSON
  • GET /health — vérifie que l’application est opérationnelle
Format attendu : entrée JSON — sortie JSON.
2.3 — Pipeline DevOps (CI/CD)

Mettre en place un pipeline CI/CD simple avec GitHub Actions ou GitLab CI.

  • Installation des dépendances
  • Exécution d’un test simple
  • Construction de l’image Docker
Aucun déploiement cloud ni registry Docker n’est exigé.
2.4 — Conteneurisation

Conteneuriser l’application avec Docker.

  • Créer un fichier Dockerfile
  • Construire l’image
  • Lancer le conteneur localement
# Construction de l'image
docker build -t ml-api .

# Lancement du conteneur
docker run -p 8000:8000 ml-api
2.5 — Monitoring

Mettre en place un monitoring minimal de l’application.

  • Logs des requêtes (entrée et sortie)
  • Compteur de prédictions
  • Nombre total de requêtes
L’utilisation de Prometheus ou d’un outil équivalent est facultative.

La priorité est donnée à la cohérence du pipeline, à la qualité de l’intégration et au bon fonctionnement global du projet. Un modèle simple mais correctement intégré dans une chaîne DevOps/MLOps fonctionnelle sera toujours mieux évalué qu’un modèle complexe mal déployé.
